⏺ Record a new test

Opens a real browser for you to click through the flow manually — log in as the role you picked, do the flow, then close the recorder window to finish. The recording is enriched into a test automatically once you close it.

🔧 Fix an existing test

Pick an existing test, then choose how to fix it. Both land in the review queue above as a proposal — never applied to the real test until you approve.

Update — scenario changed? Re-records the whole flow from scratch and proposes it as a replacement.
Analyze & heal locators — scans every locator in the test against the app right now and proposes fixes only for the ones that no longer resolve, with a confidence score for each.
Extend (record more) — scenario grew new steps at the end? Runs the existing test's own steps to get to a logged-in starting point, then the recorder opens already there — you only record the NEW part. The new steps are spliced in before the closing logout step, never touching the rest of the test's code.

✓ Suggest assertions

For an existing test, suggests additional business-outcome assertions it could check — review-only, never auto-inserted into the file.

💬 Generate a test plan from a description

Describe a flow in plain English — produces a BDD plan, grounded only in widgets the App Scanner has actually found for that role. Unresolved steps still need recording for real; this isn't a runnable test.

🔒 Authorization boundary scan

Picks two roles and checks whether any widget that only ever showed up in the higher-privilege role's App Scan is also visible while logged in as the lower-privilege role — a real signal of an exposed action, not a guess. Requires an App Scan already run for both roles (App Scan tab). A widget being visible in the UI doesn't by itself prove the underlying action would execute for that role (Mendix often also enforces this server-side) — treat a finding as something to verify by hand, not a confirmed vulnerability.
